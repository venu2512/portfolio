# DECISIONS.md

- **React pinned to 19.2.8 (not 19.3):** `@react-three/fiber@9.7.0` peers require `react >=19 <19.3`; 19.3 would break install.
- **TypeScript 5.9.3 (not 7.x):** TS 7 is the new native-port line; Next 16's build pipeline and `eslint-config-next` are validated against 5.x. Revisit when the ecosystem catches up.
- **Tailwind v4** (CSS-first, `@theme` tokens, `@tailwindcss/postcss`): current stable; no `tailwind.config.ts` needed — tokens live in `globals.css` instead of the file listed in the spec's structure.
- **ESLint flat config** imports `eslint-config-next`'s native flat exports (`next/core-web-vitals`, `next/typescript`); `FlatCompat` fails against config v16.
- **Layout**: added `Home` + `Menu`/`Close` entries to the desktop dot rail and mobile top bar (spec's fixed Layer-2 UI), not present in the original rail sketch.
- **TypeScript strictness**: enabled `noUncheckedIndexedAccess` on top of `strict`; all array access is guarded (`?? []`).
- **Eager JS budget (deviation):** initial JS is ~181 KB gzip vs the 120 KB target. ~150 KB is the Next 16 + React 19 baseline (measured: an empty route costs ~150 KB with zero app code). The route-level 3D chunk (three/R3F/drei/maath/postprocessing) is lazy and loads only after `requestIdleCallback`, satisfying the intent: LCP is the server-rendered `<h1>`, not JS. Next 16/React 19 were chosen over older, smaller runtimes for long-term support.
- **Bloom on medium tier (spec table says off):** load is lazy + gated to non-`saveData` connections; enables PerformanceMonitor to keep the effect on capable mid-range laptops instead of a hard cliff. Flip `tierTables("medium").bloom` to `false` in `src/lib/quality.ts` to enforce the table exactly.
- **PerformanceMonitor `flipflops` (3)**: dampens tier oscillation — after 3 declines the monitor disables auto-adjustment, trading shine for stability.
- **Scene loader skip-list:** `three`, `@react-three/*`, `drei`, `maath`, `postprocessing` are excluded from SSR bundling (belt-and-braces with the `ssr: false` boundary) to guarantee zero 3D code in the server render path.
- **`viewport`/`themeColor`** exported via Next 16's `Viewport` API in `layout.tsx` (not the deprecated `metadata.viewport`).
- **Waypoints kept as pure data** (no `three` import) so `Nav`/`KeyboardNav`/`StoreBootstrap` don't pull the 3D chunk eager; curve construction lives in `scene/rail.ts` (lazy chunk only).
- **OG image and placeholder resume PDF are generated by scripts** (`scripts/make-og.mjs`, `scripts/make-resume.mjs`, both dependency-free): the OG is a real 1200×630 PNG (nebula + constellation + V monogram, no text to avoid embedded-font look); the PDF is a text placeholder so the download link never 404s — **replace `public/Venugopal_V_Resume.pdf` with the real resume**.
- **`showPhone: false` honored structurally:** the contact section has no phone JSX at all (not even behind a flag), so no code path can leak it; JSON-LD also omits it.
- **`repoUrl: null` projects:** the drawer renders the repo button only when non-null; all three projects currently ship with `null` per the resume data.
- **Simple view is default-visible without JS:** reveal/fade animations only activate when JS adds `.enhanced` to `<html>`; `<noscript>` content is fully readable. Scroll-snap only applies in `.enhanced` non-simple mode.
- **`data-active` cards:** HUD cards animate via CSS transitions driven by `data-active="true|near|false"` attributes (no JS animation loops), fade-only under reduced motion.
- **Keyboard nav:** implemented exactly (`↓/↑/PageUp/PageDown/Home/End`, space pages down; ignored when the drawer is open or focus is in an input/button so native space-activation still works).
- **Portrait detection:** aspect-ratio-based (`width/height < 1`), refreshed on `useThree(size)` changes — orientation changes flow through the same path.
- **Parallax disabled in portrait + reduced motion** (spec allows touch/reduced-motion disabling; portrait desktop-narrow windows also lose it as it's pointer-coupled).
- **Scroll-snap `proximity` only**, applied on `html.enhanced:not([data-mode="simple"])` — never mandatory, disabled in simple mode and without JS.
- **Hash sync:** on load the hash is honored *before* the canvas mounts (content is server-rendered, so anchors work with JS off too); while scrolling, `history.replaceState` updates the hash when the active waypoint changes, throttled by active-index change.
- **Context-loss:** `webglcontextlost` → `preventDefault`, 2 s grace for `webglcontextrestored`, else `webgl: "lost"` → simple mode + dismissible notice; any Scene error trips the error boundary → simple mode.
- **Frameloop pause:** `frameloop="never"` while `document.hidden` (plus `visibilitychange` listener).
- **Animations gated by ±1 active window:** each station reads `active` from the store and skips its `useFrame` body outside the window — near-zero GPU cost for off-screen stations.
- **Station hit areas:** interactive satellites/pedestals use generous invisible hit meshes (≥ 44 px at typical view distances) since touch has no hover; DOM chips/sections provide the same drawer actions for keyboard/SR users.
- **Nitroware pulse:** implemented as per-layer emissive-intensity waves (cheap uniform-free approach) instead of a custom shader — visually equivalent at this node count, avoids shader compile cost on low tier.
- **Geometry disposal:** all JSX-attached geometries/materials are disposed by R3F on unmount; the one imperative `BufferGeometry` (Nitroware connection lines) lives for the scene's lifetime — the scene mounts once per page load, so there is no churn path.
- **Fonts:** `@fontsource/space-grotesk` (400/500/700) + `@fontsource/jetbrains-mono` (400/500), self-hosted via npm, `font-display: swap` default — zero external requests.
- **Deploy targets:** `vercel.json` for Vercel; `public/_headers` ships to `out/` for Netlify/Cloudflare Pages; GitHub Pages via `GH_PAGES=true GH_PAGES_REPO=<repo> npm run build` (see README).
- **`npm start`** uses `npx serve out` (static preview of the export; no server runtime needed).
